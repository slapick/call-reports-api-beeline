# Коннектор Инфопанели: телефония Билайн

Выгружает данные Облачной АТС Билайн (https://cloudpbx.beeline.ru).
Построен на SDK [infopanel-connect](https://gitlab.itgrn.ru/infopanel/connector-sdk).

| Сущность | Метод API | Связь |
|---|---|---|
| `calls` — звонки | `GET /napis/v3/statistics/recordsChart` | `*_user_id` → `operators.user_id` |
| `operators` — сотрудники | `GET /apis/portal/abonents` | `user_id` |

Логические признаки отдаются числами 1/0 (логического типа у колонок SDK нет).
Период датасета передаётся в API (`from`/`to`); без периода выгружаются последние 30 дней.
Если за период больше 100 000 звонков, Билайн отдаёт только агрегаты — коннектор
попросит уменьшить период.

```
beeline_connector.py   коннектор (класс BeelineConnector)
beeline_templates.py   готовые датасеты, виджеты, дашборды и быстрый старт
tests/                 тесты (API Билайна подменяется ответами по схемам документации)
requirements.txt       зависимости: infopanel-connect, tzdata
requirements-dev.txt   + pytest
Dockerfile             образ сервиса
.github/workflows/     CI: тесты на Python 3.10–3.12 и сборка образа
```

|---|---|---|
| `id` | string | ID звонка |
| `date` | datetime | Дата и время начала |
| `direction` | string | Направление (INB/OUT) |
| `direction_name` | string | Направление |
| `status` | string | Статус (код) |
| `status_name` | string | Статус |
| `duration` | number | Длительность разговора, сек |
| `inbound_phone` | string | Многоканальный номер |
| `has_recording` | number | Есть запись разговора |
| `is_internal` | number | Внутренний звонок |
| `user_timezone` | string | Часовой пояс |
| `external_tracking_id` | string | Внешний ID звонка |
| `from_phone` | string | Сторона А: номер |
| `from_user_id` | string | Сторона А: логин сотрудника |
| `from_name` | string | Сторона А: сотрудник |
| `from_department` | string | Сторона А: отдел |
| `from_extension` | string | Сторона А: короткий номер |
| `from_service_name` | string | Сторона А: сервис |
| `from_service_type` | string | Сторона А: тип сервиса |
| `from_service_extension` | string | Сторона А: короткий номер сервиса |
| `to_phone` | string | Сторона Б: номер |
| `to_user_id` | string | Сторона Б: логин сотрудника |
| `to_name` | string | Сторона Б: сотрудник |
| `to_department` | string | Сторона Б: отдел |
| `to_extension` | string | Сторона Б: короткий номер |
| `to_service_name` | string | Сторона Б: сервис |
| `to_service_type` | string | Сторона Б: тип сервиса |
| `to_service_extension` | string | Сторона Б: короткий номер сервиса |
| `received_user_id` | string | Принял: логин |
| `received_name` | string | Принял: ФИО |
| `received_department` | string | Принял: отдел |
| `received_extension` | string | Принял: короткий номер |
| `employee_user_id` | string | Сотрудник: логин — *вычисляется* |
| `employee_name` | string | Сотрудник: ФИО — *вычисляется* |
| `employee_department` | string | Сотрудник: отдел — *вычисляется* |
| `employee_extension` | string | Сотрудник: короткий номер — *вычисляется* |

| `client_phone` | string | Номер клиента — *вычисляется* |
| `is_inbound` | number | Входящий (1/0) — *вычисляется* |
| `is_answered` | number | Разговор состоялся (1/0) — *вычисляется* |
| `is_missed` | number | Пропущенный входящий (1/0) — *вычисляется* |
| `answered_percent` | number | Разговор состоялся, 100/0 — *вычисляется* |
| `missed_percent` | number | Пропущенный входящий, 100/0 — *вычисляется* |
| `minutes` | number | Длительность разговора, мин — *вычисляется* |
| `hour` | string | Час начала по времени АТС, «09:00» — *вычисляется* |
| `weekday` | string | День недели по времени АТС, «1 Пн» … «7 Вс» — *вычисляется* |

`employee_*` — сотрудник АТС, к которому относится звонок: у исходящего — сторона А,
у входящего — принявший вызов (`received_*`), а если никто не принял — сторона Б.
Для отчётов «звонки по сотрудникам» группируйте по этим колонкам.

Остальные вычисляемые колонки нужны потому, что в шагах датасета нет условий «если…»:

- `client_phone` — номер собеседника вне АТС: у входящего сторона А, у исходящего
  сторона Б; у внутренних звонков пусто.
- `is_answered` — статусы «Принят сотрудником», «Принят сервисом», «Дозвонился»;
  `is_missed` — «Пропущен сотрудником», «Пропущен». Сумма флага — количество.
- `answered_percent` и `missed_percent` — те же флаги как 100/0, их среднее — доля
  в процентах (25 → «25%»). Формат `percent` в Инфопанели не умножает значение на
  100, а только дописывает знак: среднее флага 1/0 показалось бы как «0,3%».
- `hour` и `weekday` считаются в часовом поясе АТС (`userTimezone` звонка, если его
  нет — московский), а `date` остаётся в UTC. Звонок в 22:30 UTC воскресенья — это
  «01:00», «1 Пн» по Москве. Номер в начале дня недели нужен для сортировки.

## Готовые датасеты, виджеты и дашборды

Описаны в `beeline_templates.py` (формат — `docs/templates.md` в connector-sdk).
Пользователь выбирает их в галерее Инфопанели и сразу видит свои данные.
**Быстрый старт** при установке из маркетплейса создаёт источник и дашборды
«Пульс дня» и «Итоги месяца».

Во всех датасетах, кроме «Активности сотрудников», внутренние звонки исключены
(`is_internal ≠ 1`). Доли (пропущенных, дозвона) — среднее флага `is_missed` или
`is_answered`.

### Датасеты (15)

| id | Название | Период | Что внутри |
|---|---|---|---|
| `calls_today` | Звонки сегодня | сегодня | звонки, разговоры, пропущено, минуты, доля пропущенных; по часам, типам, сотрудникам |
| `callback_today` | Перезвонить сегодня | сегодня | номера с пропущенным и без разговора; список пропущенных звонков |
| `outbound_today` | Обзвон сегодня | сегодня | исходящие, дозвоны, доля дозвона — по сотрудникам и часам |
| `calls_week` | Звонки за 7 дней | 7 дней | итоги и ряды по дням: звонки, пропущенные, минуты |
| `calls_month` | Звонки за месяц | этот месяц | итоги, по дням, сотрудникам, результатам; пятёрка лидеров, кто пропускает |
| `calls_last_month` | Звонки за прошлый месяц | прошлый месяц | итоги закрытого месяца для сравнения |
| `inbound_month` | Входящие за месяц | этот месяц | принято, пропущено, доля пропущенных по дням, по статусам и линиям |
| `missed_month` | Пропущенные за месяц | этот месяц | по дням, часам, дням недели, линиям, сотрудникам; полный список |
| `lines_month` | Многоканальные номера за месяц | этот месяц | звонки, клиенты, пропущенные по номерам — отчёт по рекламным каналам |
| `load_30_days` | Нагрузка по часам и дням недели | 30 дней | звонки по часам, дням недели и таблица «день × час» |
| `outbound_month` | Исходящие за месяц | этот месяц | попытки, дозвоны, доля дозвона, «дозвонились или нет», средний разговор; разговоры до 10 секунд |
| `employees_month` | Сотрудники за месяц | этот месяц | рейтинг, доля пропущенных и средний разговор по сотрудникам |
| `departments_month` | Отделы за месяц | этот месяц | звонки, разговоры, пропущенные, минуты по отделам |
| `employee_activity` | Активность сотрудников за 30 дней | 30 дней | все сотрудники АТС и их звонки; кто без звонков |
| `clients_month` | Клиенты за месяц | этот месяц | уникальные номера, потерянные клиенты, кто звонит чаще всех |

**«Перезвонить» и «потерянные клиенты».** Звонки группируются по `client_phone`.
Номер попадает в список, если у него есть пропущенный входящий и нет ни одного
состоявшегося разговора за период, ни входящего, ни исходящего. Как только
клиенту перезвонили и поговорили, номер из списка пропадает.

**«Активность сотрудников»** строится от `operators` со связью на `calls`, чтобы
в отчёт попали и сотрудники без звонков. Период у связанного набора не задаётся,
поэтому звонки берутся за 30 дней по умолчанию коннектора.

### Дашборды (6)

| id | Название | Виджеты |
|---|---|---|
| `pulse` | Пульс дня | звонки, разговоры, пропущено, ждут звонка; кому перезвонить; по часам; сотрудники; обзвон |
| `month` | Итоги месяца | итоги месяца, по дням, входящие/исходящие (полукольцо); прошлый месяц; клиенты и потерянные; лидеры |
| `inbound` | Входящие | итоги, по дням и статусам; пропущенные по часам и дням недели; линии; нагрузка; список пропущенных |
| `outbound` | Обзвон | попытки, дозвоны, доля дозвона, средний разговор; по дням; дозвонились или нет (полукольцо); по сотрудникам; короткие разговоры |
| `employees` | Сотрудники | рейтинг; доля пропущенных и средний разговор по сотрудникам; отделы; кто без звонков |
| `clients` | Клиенты | клиенты по дням; потерянные; кто звонит чаще всех |

Ещё виджеты, которых нет на дашбордах, лежат в галерее «+ Виджет».

### Как добавить или изменить

id датасетов, веток, показателей и виджетов между версиями не меняйте: по ним
платформа узнаёт уже созданное. `tests/test_templates.py` проверяет, что каждая
колонка, на которую ссылаются шаги и показатели, существует на своём шаге
(после `fields` колонка называется подписью), и что виджеты на дашбордах не
налезают друг на друга. Логику «перезвонить» и «потерянных» тест прогоняет на
звонках из тестов коннектора.

## Запуск без Docker

```bash
pip install -r requirements.txt   --index-url https://gitlab.itgrn.ru/api/v4/projects/infopanel%2Fconnector-sdk/packages/pypi/simple   --extra-index-url https://pypi.org/simple
infopanel-connect check beeline_connector:BeelineConnector --secrets secrets.json  # {"api_token": "<токен>"}
INFOPANEL_SIGNING_SECRET=dev infopanel-connect serve beeline_connector:BeelineConnector --port 8090
```

Тесты: `pip install -r requirements-dev.txt` (с тем же `--index-url`), затем `pytest -q`.

Для правок SDK одновременно с коннектором: `pip install -e ../connector-sdk`.

## Docker

```bash
docker build -t call-reports-api-beeline .
docker run --rm -p 8090:8090 -e INFOPANEL_SIGNING_SECRET=dev call-reports-api-beeline
curl http://localhost:8090/health
```
